# 金子さんへの指示書：Meta広告用LINEファネルのUTAGE実装

## 最重要：Claude Codeへ

この作業は、金子さんの記憶・注意力・自己判断に依存させないでください。

金子さんは、複数の項目を一度に渡されると、入力漏れ・確認漏れ・URLの貼り違い・タグの付け忘れ・シナリオ停止忘れが起きやすい前提です。曖昧な返事を「確認済み」と解釈せず、Claude Codeが作業を分解し、一度に1つの確認だけを求めてください。

ただし、金子さんを責めたり、萎縮させたりする表現は使わないでください。短く、具体的に、次にやることが1つだけわかる指示を出します。

Claude Codeは、次のルールを絶対に守ってください。

1. 最初にUTAGE MCPへ接続し、接続確認が取れるまで構築を始めない
2. 既存データを読み取ってから、作成予定一覧を出す
3. 金子さんには一度に1個だけ質問する
4. 「OK」「たぶん」「それで」など曖昧な返事では、重要操作を実行しない
5. URL、日時、アカウント、LINE送信者は、実値を復唱して確認する
6. すべて下書きで作り、本番予約は明示承認後だけ行う
7. 各工程の完了時にUTAGEから設定を再取得し、証拠を提示する
8. 未確認項目は推測で埋めず、`金子さん確認待ち` として止める
9. エラーが出ても、その場しのぎで条件を外さない
10. 作業を中断するときは、完了・未完了・次の1手を必ず残す

### 金子さんへの話しかけ方

悪い例：

> 必要なURLや日時を確認して、タグとシナリオを適切に設定してください。

良い例：

> まず動画URLだけ確認します。  
> `https://utage-system.com/p/W8wW6ShW0iHd`  
> このURLで合っていれば「動画URL確認済み」と返信してください。  
> ほかの確認は、この後1つずつ聞きます。

### 返事の判定

| 金子さんの返事 | Claude Codeの扱い |
|---|---|
| `動画URL確認済み` など指定された確認文 | 確認済みとして次へ進む |
| `OK`、`たぶん`、`それで`、`いいと思う` | 不十分。実値を再掲して確認し直す |
| URLだけ送られた | 用途を確認してから登録する |
| 複数候補が送られた | 勝手に選ばず、候補を番号付きで1つ選ばせる |
| 返事がない | 進められる下書き作業だけ続け、公開操作は止める |

## 0. この指示書の目的

Meta広告からLINEへ直接登録してもらい、動画を視聴してもらった後に「AIひとり起業ロードマップ作成会」へ案内するファネルをUTAGEへ実装します。

最初から本番配信にはしません。AIまたはMCPで作成できる部分は下書きまで自動作成し、金子さんがテストアカウントで分岐・本文・リンクを確認してから公開してください。

最終ゴールはスクール成約です。ロードマップ作成会の予約が最重要の中間CVです。

## 0.1 最速で終わらせる作業方式

Claude Codeが進行役になります。金子さんに「指示書を読んで作業してください」と丸投げしてはいけません。

各工程は次の5手で進めます。

```text
Claude Codeが既存設定を読む
→ 次に作るものを1つ提示
→ 金子さんが必要な実値だけ確認
→ Claude CodeがMCPで下書き作成
→ Claude Codeが再取得して合否を出す
```

説明だけを長時間続けず、確認が取れた項目から下書き作成を進めます。ただし、本番配信・削除・既存読者への一括操作は別扱いとし、最後にまとめて承認を取ります。

### 作業開始から10分以内に終えること

- [ ] UTAGE MCPへ接続
- [ ] 接続先UTAGEアカウント名を表示
- [ ] LINE配信アカウント一覧を取得
- [ ] 既存シナリオ一覧を取得
- [ ] 既存ラベル一覧を取得
- [ ] 重複候補を一覧化
- [ ] 不足している本番値を最大5件に絞って提示

10分経過しても構築へ入れない場合は、どこで止まっているかを1行で金子さんへ伝え、次に必要な操作を1つだけ指示してください。

## 0.2 絶対に勝手に行わない操作

以下は、金子さんから完全一致の承認文を受け取った場合だけ実行します。

| 操作 | 必要な承認文 |
|---|---|
| LINE配信を予約状態にする | `本番配信予約を承認します` |
| 既存シナリオを削除する | `対象を確認し削除を承認します` |
| 既存読者へラベルを一括付与・削除する | `対象人数を確認し一括変更を承認します` |
| 既存読者を別シナリオへ一括登録する | `対象人数を確認し一括登録を承認します` |

承認前は必ず、対象名・対象人数・実行後の影響を表示してください。対象人数が取得できなければ実行禁止です。

## 0.3 作業記録

Claude Codeは各工程の最後に、次の形式で記録を更新してください。

```text
【工程名】
状態：未着手 / 作業中 / 金子さん確認待ち / 下書き完了 / テスト完了 / 本番承認待ち / 完了
作成・更新したUTAGE ID：
確認した実値：
未確認項目：
次に金子さんが行うこと：1つだけ
```

口頭で「できました」と言うだけでは完了扱いにしません。UTAGEから再取得したID・タイトル・ステータス・配信日時を証拠として残してください。

## 4. 必須ラベル（タグ）

UTAGE上では「ラベル」として作成してください。表記揺れを防ぐため、以下の英数字名をそのまま使用します。

### 流入・登録

| ラベル | 付与タイミング |
|---|---|
| `src_meta_ads` | Meta広告用のLINE登録経路から登録 |
| `line_main_registered` | 本命LINEへ登録 |
| `vsl_main_offered` | 動画案内を送信 |
| `vsl_page_clicked` | 動画ページへの計測リンクをクリック |

### 動画の状態

| ラベル | 付与タイミング |
|---|---|
| `vsl_unwatched` | 動画ページ未クリックの追撃対象 |
| `vsl_partial` | 視聴開始済み・完了未判定 |
| `vsl_completed` | 動画末尾の完了ボタンまたは作成会CTAをクリック |
| `vsl_expired` | 通常公開期間が終了 |
| `vsl_reopen_requested` | 「もう一度見る」をタップ |
| `vsl_reopened` | 24時間の再公開を開始 |
| `vsl_reopen_expired` | 再公開が終了 |

### ロードマップ作成会

| ラベル | 付与タイミング |
|---|---|
| `roadmap_offered` | 作成会の案内を開始 |
| `roadmap_page_clicked` | 申込導線をクリック |
| `roadmap_booked` | 予約完了 |
| `roadmap_canceled` | 事前キャンセル・日程変更 |
| `roadmap_noshow_1` | 初回無断欠席 |
| `roadmap_noshow_2plus` | 2回目以降の無断欠席 |
| `roadmap_completed` | 作成会を実施 |

### 営業・成約

| ラベル | 付与タイミング |
|---|---|
| `sales_in_progress` | 営業中・商談中 |
| `sales_next_meeting` | 次回面談が確定 |
| `sales_no_next_meeting` | 次回面談が未確定 |
| `sales_won` | 成約 |
| `sales_stop` | 営業停止希望 |

### オプチャ

| ラベル | 付与タイミング |
|---|---|
| `openchat_invited` | オプチャを案内 |
| `openchat_link_clicked` | オプチャリンクをクリック |
| `openchat_event_campaign` | 今回の勉強会案内対象 |
| `openchat_event_engaged` | 勉強会へ申込または参加 |

## 5. 優先順位と配信停止条件

上から順に優先します。上位状態のラベルがある人には、下位の営業シナリオを配信しません。

| 優先 | 状態 | 止めるもの |
|---:|---|---|
| 1 | `sales_won` または `sales_stop` | 集客・営業配信をすべて停止 |
| 2 | `sales_next_meeting` | VSL、作成会募集、オプチャ募集を停止 |
| 3 | `roadmap_booked` | 未視聴、一部視聴、作成会募集、再公開を停止。予約リマインドのみ |
| 4 | `sales_in_progress` | 新規の作成会募集を停止 |
| 5 | `vsl_reopened` | 未視聴・一部視聴・通常作成会募集を停止 |
| 6 | `vsl_completed` | 未視聴・一部視聴を停止し、作成会案内へ |
| 7 | `vsl_partial` | 未視聴を停止し、一部視聴へ |
| 8 | `vsl_unwatched` | 未視聴シナリオを継続 |

すべての営業メッセージには、少なくとも次の除外条件を設定します。

```text
sales_won を含まない
AND sales_stop を含まない
AND sales_next_meeting を含まない
AND roadmap_booked を含まない
```

予約リマインドには `roadmap_booked` を含む人だけを指定します。

## 6. 行動別の分岐

### A. LINE登録直後

1. `src_meta_ads`
2. `line_main_registered`
3. `vsl_main_offered`

を付与し、動画URLを送ります。

動画URLは必ずUTAGEの短縮・計測リンクを使用し、クリック時に `vsl_page_clicked` と `vsl_partial` を付与します。同時に `vsl_unwatched` を外します。

一定時間クリックがない場合のみ `vsl_unwatched` を付与し、「動画未視聴」シナリオへ送ります。

### B. 動画をクリックしたが完了していない

`vsl_partial` を付与し、「動画一部視聴」シナリオへ送ります。

動画の途中離脱をUTAGEで正確に判定できない場合は、`vsl_page_clicked` かつ `vsl_completed` なしを「一部視聴」とみなします。実再生時間を推測でラベル化しないでください。

### C. 動画視聴完了

動画末尾の作成会CTAまたは「視聴完了」ボタンをクリックしたときに、

1. `vsl_completed` を付与
2. `vsl_partial` と `vsl_unwatched` を削除
3. `roadmap_offered` を付与
4. 「動画視聴完了」シナリオへ追加

します。

### D. 作成会予約

予約完了時に `roadmap_booked` を付与し、VSL・作成会募集・再公開の各シナリオを停止します。予約リマインドだけを配信します。

リマインドにはZoom URLと日程変更URLを必ず入れます。

### E. 欠席・再予約

- 初回欠席：`roadmap_noshow_1`。最初の再予約が完了するまでは他の営業配信を停止
- 2回目以降の欠席：`roadmap_noshow_2plus`。再予約を受け付けつつ、オプチャ案内も配信
- 事前キャンセル・日程変更：無断欠席回数へ含めない
- 再予約回数に上限を付けない

### F. 商談中・成約

- 次回面談が決まったら `sales_in_progress` と `sales_next_meeting` を付与
- 次回面談が決まらなければ `sales_no_next_meeting` を付与し、必要な営業フォローを再開
- 成約時は `sales_won` を付与し、すべての集客・営業シナリオから外す
- 長い場合は3回程度まで面談を持ち越してよい

### G. 未予約者・欠席者

作成会へ予約しなかった人、2回目以降の欠席者はオプチャへ案内します。オプチャ内のZoom勉強会は週2〜3回開催する可能性があるため、固定ステップではなく開催ごとのキャンペーンとして作成します。

本命の作成会募集と重なった場合は、本命の作成会を優先します。

## 7. 金子さんが手作業で行う部分

次の作業はAIへ丸投げせず、金子さんが確認または入力してください。

1. UTAGE MCPの初回認証と対象アカウントの選択
2. 使用するLINE配信アカウント・LINE送信者の確定
3. 本番の作成会申込URL、Zoom URL、日程変更URL、オプチャURLの入力
4. 個別締切日時の確定
5. 動画末尾CTAで実際にラベルが付くかの動作確認
6. 作成会の参加・欠席・商談・成約ステータスの最終確認
7. テストLINEで全分岐を受信
8. 下書きから配信予約へ変更する最終承認

成約・営業停止・予約済みの人に営業LINEが届かないことを最優先で確認してください。

## 8. AI・UTAGE MCPで自動化する部分

UTAGE MCPを接続できるAIでは、次の作業を自動化できます。

- LINE配信アカウントと既存シナリオの一覧取得
- 必要なシナリオの新規作成
- ラベルの一覧取得・新規作成・更新
- CSV本文からLINEステップメッセージを下書き作成
- 配信日時、配信条件、URLアクションの設定
- 読者ラベルの付与・削除
- テスト送信
- メッセージ本文・設定の再取得と照合
- 送信数・クリック率などの配信統計の取得

メッセージ作成・更新・削除・統計はUTAGE上で「プレビュー機能」とされているため、AIには必ず下書きで作らせ、金子さんの承認なしで配信予約へ変更させないでください。

## 8.1 MCP接続をClaude Codeに確認させる手順

1. プロジェクトの `.mcp.json` に以下を設定

```json
{
  "mcpServers": {
    "utage-api": {
      "url": "https://api.utage-system.com/mcp"
    }
  }
}
```

2. Claude Codeを起動し、ブラウザでUTAGEへログイン・認可
3. Claude Codeへ次の順に実行させる

```text
UTAGEの配信アカウント一覧を取得してください。
LINE配信アカウントだけ表示してください。
選択したアカウントのシナリオ一覧を取得してください。
既存ラベル一覧を取得してください。
```

4. 取得結果に、アカウント名・アカウントID・シナリオ数が表示されることを確認

MCPが動かない場合は、管理画面を手作業で作り始めないでください。以下だけを確認します。

- MCP接続URLが正しいか
- 別のUTAGEアカウントで認証していないか
- 認可が完了しているか
- Claude Codeを再起動したか
- `UTAGEのファネル一覧を取得して` で動作するか

解決しない場合は、表示されたエラー全文を残し、MCP接続の修復を優先します。

## 9. AIへ最初に渡すプロンプト

以下をそのままAIへ渡してください。

```text
UTAGE MCPを使って、添付の「金子さんへの指示書」とCSVからMeta広告用LINEファネルを構築してください。

最初に既存のLINE配信アカウント、シナリオ、ラベル、LINE送信者を読み取り、同名データの重複作成を避けてください。

作成・更新はすべて下書き状態にしてください。本番配信の予約、既存シナリオの削除、既存読者への一斉操作は、私の明示的な承認なしで実行しないでください。

進め方：
1. 実装前に、作成予定のシナリオ・ラベル・メッセージ数・不足URLを一覧で提示
2. 私の確認後、ラベルとシナリオを作成
3. CSV本文を省略せず、指定時刻どおりLINEステップへ下書き登録
4. 各メッセージへ配信条件と除外条件を設定
5. URLアクションへ指定ラベルの付与・削除を設定
6. 作成後、全設定を再取得して指示書と照合
7. テストアカウントで確認するケース一覧を出力

不明な項目は推測で本番値を入れず、「金子さん入力待ち」としてください。

金子さんは複数の確認を一度に行うと見落としやすいため、一度に1つだけ質問してください。重要項目は「OK」だけで確認済みにせず、指定した確認文を返信してもらってください。

各工程が終わるたびにUTAGEから設定を再取得し、ID、タイトル、ステータス、配信時刻、条件、URLアクションを照合してください。「作成したはず」では完了にしないでください。

本番配信予約、既存データ削除、既存読者への一括操作は、指示書に定めた完全一致の承認文が来るまで実行禁止です。
```

## 9.1 Claude Codeが金子さんへ聞く順番

順番を入れ替えず、一問ずつ確認します。

1. 接続先UTAGEアカウント
2. 使用するLINE配信アカウント
3. 使用するLINE送信者
4. 動画URL
5. ロードマップ作成会の申込URL
6. 予約後に送るZoom URLの取得方法
7. 日程変更URL
8. オプチャURL
9. 個別締切の計算方法
10. テスト送信先のLINE友だち

確認済みの項目は二度聞きません。確認記録に実値を残します。

## 9.2 30分ごとの進捗報告

作業が30分を超える場合、Claude Codeは次だけを簡潔に報告します。

```text
完了：○件
確認待ち：○件
エラー：○件
次の30分で行うこと：1つ
金子さんに今やってほしいこと：1つ
```

金子さんに長い自由記述を求めないでください。選択肢または指定された短い確認文で回答できるようにします。

| 初回欠席 | 再予約 | 通常営業 |
| 2回目欠席 | 再予約・オプチャ | なし |
| 次回商談あり | 商談リマインド | セミナー、オプチャ |
| 成約済み | 顧客案内のみ | 集客・営業すべて |
