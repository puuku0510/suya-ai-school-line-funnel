# 出力スキーマ

## 必須成果物

1. 全体フロー
2. UTAGEタグ辞書
3. シナリオ優先順位と停止条件
4. メッセージ一覧
5. 変数辞書
6. 実装チェックリスト

## メッセージ一覧の列

| 列 | 内容 |
|---|---|
| ID | 一意なシナリオ内ID |
| シナリオ | 配信シナリオ名 |
| 対象状態 | 配信時に必要なタグ・状態 |
| 配信タイミング | 登録・開催・視聴などの基準からの相対時刻 |
| 目的 | その1通で動かす意思決定 |
| 推奨形式 | テキスト、画像パネル、ボタン、カード、メール |
| 件名 | メールのみ |
| 本文 | 送信可能な完成文 |
| CTA | ボタンやリンクの文言 |
| 付与タグ | クリック・完了時に付けるタグ |
| 停止条件 | 配信直前に除外する状態 |
| 次シナリオ | 成功・失敗・期限切れ時の遷移先 |

## タグ命名

推奨形式: `[分類]_[対象]_[状態]`

例:

- `src_youtube_[campaign]`
- `kw_[benefit]_received`
- `benefit_[benefit]_clicked`
- `consult_benefit_booked`
- `seminar_main_registered`
- `seminar_main_attended`
- `vsl_main_started`
- `vsl_main_completed`
- `sales_next_meeting`
- `sales_won`
- `sales_stop`

タグ表示上は日本語でもよいが、分類・対象・状態の順序を崩さない。

## 完了監査

- 仕様書の予定通数とメッセージ行数を照合する。
- 各本文の変数を変数辞書と照合する。
- 予約・登録・成約の停止条件を全行で確認する。
- 参加不明者へ断定的な欠席文を送らない。
- 強い希少性表現に事実根拠があるか確認する。
- 媒体固有の語が別媒体へ混ざっていないか確認する。
